# Anti Slop: Rules for AI Coding Agents

Follow these rules whenever generating or building UI for a website, web app, or any interface.
The goal: the design should feel crafted by a designer, not generated by AI.

## Hard Gate Rules (Absolute, No Exceptions)

1. **R-02 Copywriting**: FORBIDDEN em dash character (`—`) in text. Use comma, period, colon, or parentheses instead. Natural, human voice only.
2. **R-03 Mobile Responsiveness**: Mobile layout must be deliberate, not an afterthought. Zero horizontal overflow, no clipping text, minimum 44px tap targets.
3. **R-17 Data & Numbers**: FORBIDDEN numbers and statistics without a real source (e.g. "10K+ Users", "99.9% Uptime").
4. **R-18 Testimonials**: FORBIDDEN fake testimonials, AI avatars, random fictional reviews.
5. **R-23 Clarification**: Never generate final logos, avatars, or company identities without confirmation; use clean, honest placeholders (`[LOGO]`).
6. **R-24 Navigation**: FORBIDDEN placing navbar links to non-existent sections.
7. **R-25 Color Contrast**: All text must meet WCAG AA (4.5:1 for normal text, 3:1 for large text). No grey-on-grey.
8. **R-26 Interactive Elements**: Every interactive element must have a real destination/handler, or be removed. No dead buttons.
9. **R-27 UI States**: Every data UI must provide at least three states: Empty State, Loading State, and Error State.
10. **R-28 FAQ**: FORBIDDEN generic template FAQ questions. Only address real product concerns.
11. **R-32 Keyboard Accessibility**: Full keyboard navigation (`Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape`) with visible focus outlines.
12. **R-34 Themes**: If shipping a theme toggle, both light and dark modes must be fully verified and functional.
13. **R-35 Verification**: Always build and inspect interactive elements before declaring done.
14. **R-36 No Fabricated Claims**: No fake security badges ("SOC 2", "ISO 27001", "300% faster") without empirical proof.

## Purpose-Gate Rules (Allowed Only With Stated Reason)

- **R-01 Gradients**: No generic purple/blue or neon gradients as default background. Allowed only when serving explicit brand hierarchy.
- **R-04 Icons**: No generic sparkle, magic, or lightning icons. Every icon must be genuinely relevant to content.
- **R-06 Typography**: No random monospace headers or extreme uppercase tracking without purpose.
- **R-07 Backgrounds**: No generic dot grids, blueprint lines, or graph paper unless tied to technical product character.
- **R-08 Button Arrows**: Avoid attaching arrows (`→`, `↗`) to every button purely as decoration.
- **R-09 Badges**: Avoid generic capsule badges ("AI Powered", "Beta", "New") stacked with glow and borders.
- **R-10 Glassmorphism**: Dose cap on max 1-2 elements. Never apply simultaneously to navbar, cards, modals, and sidebar.
- **R-12 Shadows**: Use shadow selectively as an elevation marker, not a default floating state for every box.
- **R-14 Feature Cards**: Avoid monotonous rows of identical feature cards. Vary layout by content priority.
- **R-15 CTAs**: Avoid generic "Get Started", "Learn More", "Explore". Use contextual actions ("Buat Tiket Setor", "Lihat Pasokan B2B").
- **R-16 Buzzwords**: Cut words like "AI-Powered", "Seamless", "Revolutionary", "Cutting-edge". State concrete facts.
- **R-29 Color Limit**: Limit active palette to 2-3 core colors + 1 intentional accent.

## Craftsmanship Standard

- **C-1 Intentionality**: Every decision has an articulable one-line reason.
- **C-2 Functional Completeness**: Every button works or does not exist.
- **C-3 Content-Driven Composition**: Sections exist because content demands them, not template defaults.
- **C-4 Resilience**: Tested on mobile (375px), tablet, and desktop (1440px).
- **C-5 Evidence Over Claims**: Real data or honest placeholders.
